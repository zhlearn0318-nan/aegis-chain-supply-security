# MaliciousSkillBench 1,384 条全量结果与 P2 改进路线

> 实验日期：2026-08-31
> 实验状态：主实验已冻结；不得用本结果直接调规则后再把同一测试集宣传为“独立最终测试”
> 数据范围：OpenClaw Skill 静态与纯指令动态准入

## 1. 为什么从 40 条扩大到 1,384 条

原 40 条第三方 Skill 的优势是目录真实、可安装、部分样本可进入容器；不足是规模小、来源和标签强度不统一。主实验改用论文 **MaliciousSkillBench: A Comprehensive Benchmark for Malicious Agent Skill Detection** 的官方 Source-Disjoint test 全集：

- 共 1,384 条，恶意 839 条、良性 545 条；
- 不再二次抽样，避免抽样偏差；
- 训练、验证和测试来源隔离，适合检验跨来源泛化；
- 带来源、攻击类别、结构家族和证据类型元数据；
- 数据提交、原始文件哈希、落地文本哈希和评测配置全部固定。

因此当前证据结构是：**1,384 条权威静态文本主实验 + 40 条真实完整包补充实验**。两者不混算一个准确率。

## 2. 实验是否真实运行

本轮为真实运行，不是模拟：

1. Cisco Skill Scanner 以 `scan-all` 对可落地样本执行真实批量扫描；
2. Aegis 对每条样本运行 P0 静态上下文、数据流、能力一致性和语义规则；
3. 本地 Qwen 仅在现有策略认为语言歧义时调用；
4. 非静态阻断样本进入 P1 纯指令三场景审计；
5. 每条结果独立落盘，可中断续跑；
6. 扫描清单不含标签，三组结果完成后才合并官方真值。

批量 Cisco 扫描约 31 秒；逐条 P0/P1 阶段本次约 64 秒。最终 16 条为失败关闭 UNKNOWN：其中 5 条被主机内容防护阻止原样落地，11 条不满足 Cisco 严格 Skill frontmatter 结构。系统没有关闭 Defender，也没有把失败解释为安全。

## 3. 总体结果

| 系统 | 恶意不放行召回 | 恶意直接 BLOCK | 良性自动 ALLOW | 良性直接 BLOCK | REVIEW | UNKNOWN |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Cisco-only | 3.2% | 1.5% | 94.9% | 1.1% | 20 | 16 |
| Cisco + P0 | 15.6% | 1.7% | 74.1% | 5.3% | 213 | 16 |
| Cisco + P0 + P1 | 15.6% | 1.7% | 74.1% | 5.3% | 213 | 16 |

配对结果：P0 相对 Cisco 将恶意“不自动放行召回”提高 12.4 个百分点，同时使良性自动放行率下降 20.7 个百分点。P1 相对 P0 的决策增量为 0。

这组结果不能包装成“系统效果优秀”。它证明了两个事实：

1. 当前 P0 确实发现了 Cisco 漏掉的一部分风险；
2. 当前规则的跨来源泛化仍不足，召回提升伴随明显复核工作量，必须进入 P2 语义检测和误报控制改进。

## 4. 为什么当前召回仍低

### 4.1 厂商静态规则主要擅长显式模式

Cisco 命中的风险主要是管道污点流、工具链滥用、显式提示注入、隐藏文件和命令模式。812 条恶意样本仍被 Cisco 自动放行，说明大量样本并不包含这些显式代码或关键词结构。

### 4.2 P0 本地模型实际只审查了 11 条

现有模型不是“全量恶意语义分类器”，只在确定性规则发现孤立的隐瞒、覆盖或确认绕过语言时复核。本次只产生 11 次真实模型调用，因此不能期待它覆盖数百条隐蔽后门指令。这个结果也说明下一步应扩大“哪些样本进入语义审查”的范围，而不是简单换更大的模型。

### 4.3 当前 P0 的主要新增召回来自动条件触发规则

在 131 条恶意非放行样本中，`AEGIS_SEMANTIC_CONDITIONAL_RISK_TRIGGER` 出现 80 次，说明延迟/条件触发是有效方向。但同一规则也出现在 105 条良性非放行样本中，是当前最主要误报来源。该规则需要结合动作对象、文档语境和安全禁止语境进行校准，不能继续只扩大关键词。

### 4.4 P1 没有增量是数据形态决定的

官方主实验提供的是 Skill 文本快照，没有随包脚本。P1 正确选择“纯指令审计”，容器代码执行次数为 0；而纯指令路径与 P0 使用相同语义证据，单调融合后不会改变决策。P1 的实际动态增量必须在 40 条完整包和后续真实第三方完整 Skill 上测量，不能用静态文本集伪造。

## 5. 当前主要误报与漏报

### 5.1 漏报

- P0 仍自动放行 708 条恶意样本；其中 SRC009 占 622 条。
- 记忆/目标操纵类非放行召回约 9.3%。
- 数据外传/披露类非放行召回约 5.8%。
- 权限/工具滥用类约 25.9%。
- 说明现有规则对“自然语言目标重写、渐进式操纵、语义后门”覆盖不足。

### 5.2 误报与复核负担

P0 有 141 条良性样本未自动放行，主要非 INFO 规则为：

- `AEGIS_SEMANTIC_CONDITIONAL_RISK_TRIGGER`：105 次；
- `AEGIS_REMOTE_FETCH_PIPE_SHELL`：17 次；
- Cisco `PIPELINE_TAINT_FLOW`：14 次；
- `AEGIS_SEMANTIC_CONCEALED_RISKY_BEHAVIOR`：7 次。

需要优先识别示例、检测规则、安全禁止语句、安装说明与真实操作命令的差别，避免把“文档提到风险”当成“Skill 要求实施风险”。

## 6. P2 下一步路线

### P2-1：建立独立开发协议，不污染本次测试结论

使用官方 train/validation 建立开发与选择流程：

- train 用于训练轻量文本模型；
- validation 用于阈值、规则和提示词选择；
- 本轮 test v1 永久保留，不删除、不覆盖；
- 改进后的结果若再次在同一 test 上运行，必须标为“看过 test 后的诊断性 v2”，不能声称独立盲测。

### P2-2：复现论文轻量文本基线并集成成证据源

优先复现 TF-IDF + 线性分类器，而不是先让 7B 模型逐条全量推理。理由：

- CPU 可运行，适合 Windows 一键部署；
- 论文已经证明这类方法在 Source-Disjoint 上明显强于现有关键词扫描；
- 可输出分数和高贡献 n-gram，便于评委理解；
- 可以作为“进入 REVIEW 或调用本地模型”的预筛证据，不允许单独把样本直接 BLOCK。

阈值在 validation 上按“良性误拦上限 + 恶意召回最大化”选择，避免追求单一准确率。

### P2-3：扩大本地模型审查范围，但保持成本受控

将当前“11 条歧义语言才调用模型”改为分层路由：

1. 确定性高危证据直接按现有规则处理；
2. 轻量文本模型高风险或多条弱证据冲突时调用本地 Qwen；
3. Qwen 只可把不确定样本提升到 REVIEW，不可单独 BLOCK；
4. 模型输出继续只保留结构化理由码，不保留原始恶意文本。

### P2-4：修正三类主要误报规则

在 validation 开发集上分别做消融：

- 条件触发必须与敏感动作/外传/越权目标同一局部窗口，并排除安全禁止和测试说明；
- 远程下载与 Shell 只有形成可执行链或缺少完整性控制时才直接升级；
- Cisco 管道污点流若仅处于示例、安装文档或不可达片段，进入证据不足复核，不直接视为完整攻击链。

### P2-5：完整包动态补充实验

继续使用 40 条完整第三方 Skill，并新增安全来源的完整包。只对可确认安全/普通样本执行容器；已知恶意或脆弱样本只做静态审计。动态实验重点报告：入口发现率、有效执行率、行为命中、清理成功、ALLOW/REVIEW/BLOCK 增量，而不是与 1,384 条文本主实验混算。

## 7. 参赛汇报口径

建议如实表述：

> 我们把原 40 条真实 Skill 试验扩展为 1,384 条权威 Source-Disjoint 主实验。结果显示，P0 相比 Cisco 将恶意非自动放行召回提高 12.4 个百分点，但也带来 20.7 个百分点的良性自动放行损失；这暴露出条件触发规则误报和隐蔽语义漏报。我们没有隐藏失败，而是据此建立独立开发协议，并将论文轻量文本模型、本地 Qwen 复核和完整包动态试验作为 P2 的针对性改进。

这比宣称“准确率很高”更有研究可信度，也能清楚说明静态规则、语义模型和动态审计各自解决什么问题。
