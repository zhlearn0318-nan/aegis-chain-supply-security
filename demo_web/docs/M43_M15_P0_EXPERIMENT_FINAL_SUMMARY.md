## 3. 最适合答辩展示的三条证据链

### 3.1 静态组件不是工具堆叠

E01 使用 S0—S6 消融表量化每层贡献。Aegis 确定性规则和语义规则均带来可测增量；轻量模型把62个恶意样本从 ALLOW 提升为 REVIEW。Qwen 在该锁箱上最终决策增量为0，因此报告没有把“使用大模型”包装成虚假提升。

### 3.2 动态三轮不是重复执行

E03 中30个风险孪生均首次在 adversarial 轮触发；三轮把风险非放行从22/30提高到30/30，而P95耗时仅为单轮保守估计的1.15倍。E04再用编码、拼接、间接调用、落地执行、延迟触发、父子进程、分步数据流和超时八类变形复核，风险与安全对照各24个均达到预期。

### 3.3 OpenClaw 阻断是真实闭环

E05 通过正式插件入口执行扫描并核对安装结果、审计记录、API和PDF。所有非 ALLOW 样本均未安装；并发请求不会启动多份扫描；模型、Cisco或Docker不可用时均失败关闭。现场可展示从上传 Skill 到作出 ALLOW/REVIEW/BLOCK，再到审计报告的全过程。

## 4. 必须诚实说明的限制

1. E01 validation 已用于错误分析，后续修改规则后不能继续称它为未见锁箱；
2. E04 使用受控风险孪生证明检测机制，没有执行已知真实恶意第三方代码；
3. 当前动态遥测以 Python、Node、Shell 语言探针和 Docker 隔离为主，不能覆盖原生二进制、自修改代码和直接系统调用的全部行为；
4. E06 是单人确定性归因，没有第二标注者一致性数据；
5. Docker 故障可以安全拒绝安装，但 Docker Desktop 自动自愈尚不可靠；
6. REVIEW 是失败关闭与控制误报之间的必要状态，不应把 REVIEW 误称为恶意检出或自动放行。
