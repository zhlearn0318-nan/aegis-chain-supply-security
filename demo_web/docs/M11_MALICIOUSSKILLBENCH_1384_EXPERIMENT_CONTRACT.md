# MaliciousSkillBench 1,384 条权威测试集实验合同

## 1. 目的与冻结结论

本轮不再把“40 个真实第三方 Skill”直接扩充成来源混杂、标签强度不一的 300 条集合，而采用公开论文 **MaliciousSkillBench: A Comprehensive Benchmark for Malicious Agent Skill Detection** 的官方 **Source-Disjoint test 全集 1,384 条**作为主实验。原 40 个完整第三方 Skill 继续作为包结构、可安装性和动态审计的补充实验。

本合同在第一次扫描前冻结。扫描后不得根据测试结果修改规则、阈值、模型提示词或准入策略；需要改进时必须另建开发集和实验版本，原始结果永久保留。

## 2. 数据身份

- 数据集：`ProtectSkills/MaliciousSkillBench`
- 固定提交：`d4b42ce5766a6e0359c987cf59c1007cb3795a90`
- 官方协议：`source_disjoint / test`
- 样本数：1,384
- 恶意：839；良性：545
- 选择原因：规模超过 300、标签与攻击分类公开、拆分协议冻结、测试来源与训练来源隔离，可直接回应“泛化能力”质疑。
- 不抽样原因：使用全量官方测试集可消除二次抽样偏差，并与论文口径保持一致。

## 3. 三组系统

1. `Cisco-only`：只保留 Cisco Skill Scanner 证据，按冻结的 v1.0 严重度策略决策。
2. `Cisco + P0`：加入 Aegis 静态上下文、数据流、政企规则、能力声明一致性与语义复核，按 v1.1 证据感知策略决策。
3. `Cisco + P0 + P1`：在 P0 结果上单调融合 P1。官方样本只有公开 Skill 文本快照，因此 P1 只能走“纯指令三场景语义审计”，不会执行恶意脚本。

三组共用同一次 Cisco 扫描产生的底层证据，避免重复运行引入不必要波动。扫描阶段读取的清单不含标签；只有三组扫描输出全部完成后，评测阶段才从独立目录合并真值。

## 4. 研究问题与判断门槛

研究问题：P0 与 P1 是否能相对 Cisco 基线提高恶意 Skill 的“不自动放行召回”，同时保持可接受的良性自动放行率？

- 原假设：新增能力没有带来可重复的主要指标改善。
- 备择假设：至少一项主要安全指标改善，且对应良性指标下降不超过 5 个百分点。
- 不把 `REVIEW` 伪装成 `BLOCK`：分别报告恶意不放行率、恶意直接阻断率、良性允许率、良性阻断率及 REVIEW/UNKNOWN 分布。

## 5. 指标

主要指标：恶意不自动放行召回率、恶意直接阻断率、良性自动放行率、良性阻断率、二分类 BLOCK 宏平均 F1、平衡准确率。

次要指标：每来源结果、每攻击类别结果、决策分布、失败/UNKNOWN 率、P50/P95 延迟、模型调用数、P1 代码动态执行覆盖率。正式报告同时给出配对差异与置信区间，不只给单个准确率。

## 6. 已知边界

- 官方 Source-Disjoint 测试集的来源与标签分布并非完全独立，必须按来源分层报告，不能只报告总准确率。
- 主实验是公开静态文本检测，不等价于对完整 Skill 包执行容器动态检测。
- 40 个真实包补充集用于展示完整目录扫描和安全样本的容器执行；已知恶意或脆弱第三方代码不执行。
- 数据集作者生成的元数据、衍生标注、拆分清单和数据库组织采用 CC BY 4.0；第三方 Skill 文本仍保留其上游许可边界。
