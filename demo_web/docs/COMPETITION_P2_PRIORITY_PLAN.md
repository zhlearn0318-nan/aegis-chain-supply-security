# Aegis Chain P2 参赛增强优先级计划

> 文档状态：实施中；优先级 1 主实验已完成
> 编制日期：2026-08-31
> 目标：在 P0/P1 已完成的基础上，优先实施能够直接提升现场演示效果、检测可信度和研究创新性的 P2 工作
> 范围：挑战杯“揭榜挂帅”赛题最终作品，不以完成全部政企生产化能力为目标

## 1. 当前基础

目前系统已经完成：

- P0：安装前静态审计、自然语言语义分析、声明—实现一致性分析、OpenClaw 控制面规则、本地小模型复核；
- P1：纯指令、Python、Node.js、Shell Skill 路由，典型/边界/对抗三轮 Docker 隔离试运行；
- OpenClaw 正式准入：上传或安装 Skill 时自动调用安全引擎，根据证据返回 ALLOW、REVIEW 或 BLOCK；
- 本机验收：真实 Docker 动态样本6/6、OpenClaw端到端6/6、后端495项测试通过。

P0/P1 已经构成完整的参赛核心闭环。P2 不需要全部完成，应优先选择能够被评委直观看到、能够用实验数据证明价值的工作。

## 2. 从现场演示效果考虑

### 2.1 真实第三方 Skill 准入演示

**优先级：P2-必须**

准备三类真实第三方 Skill：

1. 正常 Skill：静态和动态审计通过，最终 ALLOW 并安装；
2. 可疑 Skill：存在未声明能力或证据不充分，最终 REVIEW；
3. 恶意 Skill：观察到敏感读取、危险命令或其他高危行为，最终 BLOCK。

现场演示链路：

```text
上传或选择 Skill
  → P0 静态扫描
  → 语义与声明—实现分析
  → P1 Docker 三轮隔离试运行
  → 静态与动态证据融合
  → ALLOW / REVIEW / BLOCK
  → 安装或阻断
```

验收标准：

- 三类决策均有可重复演示样本；
- 页面展示真实扫描和容器运行日志，不使用模拟动画；
- ALLOW 样本可以完成安装；
- REVIEW 样本不能被误显示为安全；
- BLOCK 样本不会进入正式 Skill 安装目录；
- 每次演示结果均产生审计记录。

### 2.2 检测过程和证据链可视化

**优先级：P2-必须**

页面应清楚展示：

- 当前处于哪个扫描阶段；
- P0 检查了哪些文件和说明文本；
- P0 找到的风险及其上下文；
- P1 选择了哪个运行时和入口；
- 三轮动态输入的执行进度；
- Docker 是否满足断网、只读、非 root 等隔离条件；
- 观察到了哪些文件、网络和进程行为；
- 静态发现与动态证据如何共同形成最终决策。

推荐重点展示的案例叙事：

> 某 Skill 声称只执行文档整理，但实际运行时读取了凭据诱饵文件，因此声明与真实行为不一致，系统将其阻断。

验收标准：评委不阅读源代码，也能在一分钟内理解系统为什么放行、复核或阻断某个 Skill。

### 2.3 自动生成正式审计报告

**优先级：P2-高**

一次准入结束后，应能导出 PDF 或结构化报告，至少包含：

- Skill 名称、来源、文件哈希和扫描时间；
- Cisco 与 Aegis 静态发现；
- P0 语义和能力一致性结论；
- P1 动态行为与三轮执行状态；
- Docker 隔离证明；
- 最终决策及形成原因；
- 风险修复建议；
- 审计记录编号和完整性校验值。

验收标准：现场扫描结束后可以立即下载，报告内容与页面决策一致。

### 2.4 第二台 Windows 电脑部署演练

**优先级：P2-高**

至少在一台非开发电脑上完成：

- OpenClaw 和插件安装；
- Cisco 扫描器环境准备；
- Docker 固定镜像验证；
- Ollama 与本地 Qwen 模型准备；
- Aegis 安全中心打开；
- 一个安全和一个恶意 Skill 的完整准入演示。

不要求比赛前建设完整生产发布体系，但应保存：

- 部署电脑基本环境；
- 一键安装日志；
- 成功页面截图或演示视频；
- 失败及解决过程；
- 总部署时间。

这项证据可以证明作品不是只能在开发者电脑上运行。

## 3. 从检测效果和研究创新性考虑

### 3.1 权威数据集三版本对比实验

**优先级：P2-必须，研究价值最高**

选择权威论文公开数据集和已有真实第三方 Skill 集，比较：

| 实验版本 | 能力范围 | 目的 |
| --- | --- | --- |
| Cisco 基线 | Cisco Skill Scanner | 证明厂商工具原始效果 |
| 静态增强 | Cisco + Aegis P0 | 证明语义和一致性分析的价值 |
| 完整系统 | Cisco + P0 + P1 | 证明动态审计带来的增量价值 |

至少报告以下指标：

- 恶意/可疑样本非自动放行召回率；
- 正常样本自动放行率；
- 正常样本直接 BLOCK 率；
- REVIEW 率；
- UNKNOWN 率；
- 平均静态扫描时间；
- 平均动态扫描时间；
- 动态有效执行率；
- 各类风险的命中情况。

必须明确数据标签边界：论文中的 `safe` 不等于绝对安全，`suspicious` 也不能全部当作确认恶意。

验收标准：能够用数据回答“P0/P1 相比只使用 Cisco，实际提升了什么”。

### 3.2 消融实验

**优先级：P2-必须，研究创新性强**

分别关闭某项能力并重新评测：

1. 关闭语义分析；
2. 关闭声明—实现一致性分析；
3. 关闭本地小模型；
4. 关闭动态审计；
5. 动态审计只运行一轮；
6. 动态审计运行完整三轮。

重点观察：

- 哪个模块减少了正常 Skill 的误报；
- 哪个模块发现了静态扫描遗漏的风险；
- 本地小模型是否真正改善了歧义文本判断；
- 三轮输入相对单轮增加了哪些风险触发；
- 各模块带来了多少额外扫描时间。

验收标准：每项核心创新都能对应至少一个可量化的效果变化，而不是只说明“系统使用了该技术”。

### 3.3 误报、漏报和典型案例分析

**优先级：P2-必须**

至少整理以下案例：

- Cisco 误报，但 P0 识别为安全禁止语境；
- Cisco 发现高危关键词，但文件实际属于示例或测试；
- Skill 文档没有声明网络或文件能力，P0 发现实现不一致；
- 静态扫描未形成阻断，但 P1 观察到危险行为；
- P0/P1 仍然无法可靠判断，只能进入 REVIEW；
- 当前系统仍然遗漏的风险类型。

每个案例说明：

1. 样本原始标签和功能；
2. Cisco 结果；
3. P0 新增证据；
4. P1 新增证据；
5. 最终决策；
6. 为什么正确或为什么仍然失败；
7. 后续改进方向。

主动说明失败样本和能力边界可以增强实验可信度。

### 3.4 增加一项独立底层遥测旁证

**优先级：P2-可选**

可选择 Windows ETW、Linux syscall/strace、Falco 或 eBPF 中的一项，完成最小旁证实验。例如：

> Node.js Skill 启动 Shell 时，Node 语言钩子与系统级进程监控同时观察到该行为。

该实验可以证明系统认识到语言钩子可能被绕过，并尝试使用独立证据进行交叉验证。

验收标准：至少一个动态风险能够同时产生语言级和系统级两份可关联证据。

不建议比赛前投入大量时间建设完整 eBPF 平台，避免影响核心演示稳定性。

## 4. 比赛前不建议优先实施的工作

以下能力对真实政企生产系统有价值，但对当前比赛的直接得分帮助较低：

- 完整企业多租户权限体系；
- 对接企业 SIEM；
- WORM 不可篡改存储；
- 高可用集群；
- 多机消息队列和任务调度；
- 大型规则审批平台；
- 一次性支持大量新编程语言；
- 完整生产级 eBPF 检测平台。

这些工作可以写入后续规划，用来证明系统具备生产化思考，但不应在比赛核心实验和现场演示完成前占用主要开发时间。

| 3 | 误报与漏报分析 | 提升研究可信度 | 必须 |

## 7. 最终参赛口径

演示方面应让评委看到：

> Aegis Chain 不只是生成扫描报告，而是能够在 OpenClaw 安装 Skill 前完成静态理解、隔离试运行、证据融合和安装阻断。

研究方面应让评委看到：

> 系统不是简单堆叠 Cisco、规则和大模型，而是通过基线对比、消融实验和错误分析，证明 P0/P1 的每个关键模块对减少误报或发现真实风险具有可量化价值。

一句话概括 P2 参赛策略：

> 优先把“看得见的完整闭环”和“经得起质疑的实验数据”做好，生产级控制面作为后续规划展示，不在比赛前盲目扩张。
