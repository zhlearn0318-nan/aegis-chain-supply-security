# M33 E03 动态 0/1/3 轮消融结果

> 结论：保留 `typical + edge + adversarial` 三轮作为默认动态审计策略。

## 核心结果

| 系统 | 风险孪生非放行 | 预期动态规则召回 | 原始脚本动态 ALLOW | P50 总耗时 | P95 总耗时 | 脚本轮次数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| D0 静态 v5 | 22/30（73.3%） | 0/30 | 不适用 | 7.50 s | 11.66 s | 0 |
| D1 typical | 22/30（73.3%） | 0/30 | 6/6 | 10.54 s | 15.67 s | 36 |
| D3 三轮 | 30/30（100%） | 30/30（100%） | 6/6 | 12.70 s | 18.02 s | 108 |

D3 相比 D1 的风险非放行召回提高 26.67 个百分点，补齐全部五类风险；P95 总耗时比为 1.15，低于合同上限 2.5。静态 ALLOW→动态非放行 8 个，静态 REVIEW→动态 BLOCK 15 个。

## 首次触发

30 个受控风险孪生的预期规则全部首次出现在 adversarial 轮。该结果与数据合同中的延迟触发设计一致，说明 typical 单轮没有覆盖这些边界/对抗输入；它不是“多跑两遍相同输入”带来的随机收益。

## 工程解释

三轮仍只创建每个 Skill 一个容器实例，但在容器内执行三组固定输入。D1 耗时来自同一真实三轮运行的前缀归因：具备逐轮耗时的记录扣除后两轮，缺少逐轮耗时的 Node/Shell 记录采用总耗时三分之一作为保守下界。因此 1.15 是偏向不保留 D3 的上界比较，不是一次独立的一轮容器实测。

## 质量事件

v1 前缀重放只识别 Python 的轮次字段，没有识别 Node 的 `exit_code + timed_out` 结构，错误产生 3 个原始 Skill 动态非放行。v1 已保留失败回执；v2 增加双结构测试并复用哈希一致的静态结果，没有重新执行第三方脚本。
