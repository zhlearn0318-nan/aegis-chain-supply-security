# M32 E03 前缀重放 v2 修订

v1 的静态 v5 扫描有效，但前缀完整性判断只识别 Python 轮次的 `execution_status` 字段，没有识别 Node 轮次的 `exit_code + timed_out` 字段，导致 3 个官方原始 Skill 被错误添加“遥测不完整/执行不确定”发现。该结果判为无效重放，不作为动态误报证据。

v2 同时验证两种已冻结轮次结构。对于缺少逐轮耗时的 Node/Shell 记录，D1 动态耗时采用三轮总耗时的三分之一作为保守下界，使 D3/D1 比值成为偏向不保留三轮的上界。v1 的静态 v5 结果按哈希复用，不重新调用 Cisco，也不重新执行动态脚本。
