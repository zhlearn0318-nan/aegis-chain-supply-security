# M36 E04 动态审计对抗鲁棒性实验结果

## 1. 结论

E04 最终 v4 通过全部预注册判定门。在 24 组单因素配对、48 个受控 Skill、144 次脚本轮次执行中：

- 风险变形非自动放行：24/24（100%）；
- 预期风险规则命中：24/24（100%）；
- 安全对照 ALLOW：24/24（动态误报 0）；
- Python、Node、Shell 分别为 8/8 风险检出，安全对照误报均为 0；
- 三轮证明、安全配置门、容器清理、输入树不变、无外联成功均为 100%；
- 基础设施失败回退为 ALLOW：0 次。

因此，在本实验定义的八类简单变形范围内，没有样本通过编码、路径拼接、间接调用、落地执行、延迟触发、进程链、分步数据流或超时来绕过安装前动态准入。

## 5. 首轮反例与修复

v3 是第一次完成 48 个真实容器执行的有效结果，未被覆盖：

- 风险非放行 24/24；
- 预期规则 22/24（91.7%）；
- 安全对照误报 1/24；
- 整体判定未通过。

原始日志证明了三个问题：

1. Node 内部把 `net.connect(options)` 参数正规化为数组，旧探针记录成 `[object Object]`，导致回环连接被误判为外联；
2. Shell xtrace 看到了变量展开后的诱饵路径，但旧采集器只提取命令名，未提取文件读取路径；
3. Node `/etc/passwd` 样本的预期标签误写为诱饵访问，实际命中敏感系统路径规则是正确行为。

v2 修订正确解析 Node 连接参数、从实际执行的 Shell xtrace 中提取受限读取命令的展开路径，并修正预期标签。修订后的工具文件被重新计算 SHA-256 并写入正式动态配置，随后全量复测，而非只复测三个问题样本。

## 6. 失败过程保留

| 运行 | 状态 | 保留原因 |
|---|---|---|
| v1 | 无 Docker CLI，48 个样本全部基础设施失败并保持非放行 | 证明缺少容器环境时不会静默 ALLOW |
| v2 | Docker 已安装，但受限任务环境看不到用户目录 CLI | 证明执行环境差异不会被计作检测成功 |
| v3 | 48/48 真实执行，发现 1 个误报、1 个 Shell 证据漏失和 1 个标签错误 | 有效反例与修复依据 |

同时修复了正式后端的一个失败闭锁缺陷：Docker CLI 发现失败此前会向上抛出异常并中断批次，现在会产生结构化 `DOCKER_CLI_NOT_FOUND` 结果和非放行决策。

## 8. 对独立系统遥测的决策

**决策：保留为生产增强项，不作为当前 E04 通过的前置条件。**

本轮证明语言级探针足以覆盖约定的简单变形，并已经消除一个真实误报和一个真实 Shell 漏证据。但 Shell 仍依赖受限命令集合，Python/Node 仍依赖语言运行时钩子。对于原生二进制、未知语言、自修改代码、直接系统调用或探针规避，独立系统遥测（例如 eBPF/ETW/系统调用级观测）仍有必要。参赛版本可以诚实表述为“语言探针 + Docker 隔离的可解释准入”，不能表述为内核级全行为检测。

## 10. 能力边界
