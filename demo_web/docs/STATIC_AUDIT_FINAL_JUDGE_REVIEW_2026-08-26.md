# Aegis Chain 静态审计最终评委复核

> 复核日期：2026-08-26
> 复核对象：供应链安全模块静态审计与 OpenClaw 安装准入
> 比赛结论：**可冻结并进入材料准备**
> 生产结论：**NO-GO**

## 1. 总体判断

当前系统已经不是“调用两个开源扫描器的演示脚本”，而是具备统一 Finding、四态策略、失败关闭、检测覆盖说明、密封回归、安装前准入、审计链和真实 OpenClaw 闭环的研究型工程原型。用于挑战杯揭榜挂帅的供应链安全静态部分，完成度已经足以冻结；继续无边界加规则的收益低于破坏稳定性和材料进度的风险。

## 3. 已闭合的静态能力

- Skill：Cisco Skill Scanner + Aegis 规则、敏感数据流、不可信执行流、政企控制和覆盖缺口；
- MCP：Cisco MCP Scanner + Tool/Prompt/Resource 离线对象策略；
- Python依赖：pip-audit、完整性规则和SBOM；
- OpenClaw Skill：真实安装前 allow/block/失败关闭；
- OpenClaw Plugin：目录型原生包、入口、生命周期、依赖、二进制覆盖和随包 MCP 定义；
- 安全工程：扫描器最小环境、合成 profile、审计落库失败阻断、SQLite 哈希链和部署前四样本检查；
- 治理：125条 Aegis 静态规则全部登记，新增 Plugin 家族明确不冒充 M3 Skill 密封回归结论。

最终补强后，有 Node 依赖的 Plugin 即使版本和锁文件存在，也会因尚无漏洞证据进入 REVIEW，不再被错误 allow。

## 4. 仍未完成但不阻断比赛冻结的事项

1. 配置型 OpenClaw MCP：`mcp add/set/configure` 不经过 install policy，需要平台在配置提交前调用独立准入接口或包装器。
2. Node Plugin 漏洞扫描：当前缺少 npm/OSV 真实漏洞证据时 REVIEW；生产化应接入锁文件级 OSV/npm audit 后再允许。
3. Plugin 数据集：当前是控制 fixture 与真实安装闭环，不能用 SkillTrustBench 指标替代 Plugin 检出率。
4. 外部审计：SQLite 哈希链不是 WORM、可信时间戳或 SIEM；生产环境需外送事件与链头。
5. 上游版本：稳定版可确认 warn、Beta Windows ACL 门仍受 OpenClaw 版本限制。
6. 单文件/归档 Plugin：当前失败关闭，未自动解包放行。

这些是生产化和跨生态扩展项。比赛汇报应主动说明，不能宣称“覆盖所有 Agent 供应链形式”。

## 5. 动态审计是否需要加强

若比赛主张是“静态审计为主、动态证据为补充”，当前自建哈希锁定 fixture、Docker 约束、MCP 协议调用、Marker 源到汇和内核旁证已经足够形成展示闭环，不建议在提交前执行第三方恶意样本。

若主张升级为“可安全运行未知 Skill/MCP 并给出运行时结论”，动态部分必须继续加强：独立 VM/微虚拟机隔离、完整 syscall/文件/网络遥测、内部 sinkhole、快照回滚、第三方样本治理和动态证据参与最终策略。目前不具备该生产级声明条件。

## 6. 冻结建议

- 立即冻结静态规则和默认阈值，不再使用600条回归集调参；
- 只修复会导致测试、启动、真实 allow/block 或证据复现失败的缺陷；
- 比赛演示固定使用稳定版 REVIEW→block 兼容模式；
- 汇报主线固定为“离线审查 → 统一证据 → 四态门禁 → OpenClaw 安装前拦截 → 审计追踪”；
- 把配置型 MCP、Node OSV、外部 SIEM 和未知代码强沙箱放入后续路线，不在当前成品中伪装完成。

最终判定：**静态审计比赛版本可以冻结；生产发布继续 NO-GO。**
