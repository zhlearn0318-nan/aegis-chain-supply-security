# OpenClaw Skill 安装前审计闭环——现场一键演示讲解稿

## 1. 演示目标

本次只演示一条完整、真实的业务链路：第三方 Skill 在接入 OpenClaw 前，先经过静态审计；静态结果可接受时，再进入 Docker 隔离试运行；最终由 OpenClaw 根据审计结论决定安装或阻断，并留下可校验的审计记录。

演示不是播放预录结果。脚本会在当前机器的真实 OpenClaw、真实 Docker Desktop 和真实审计策略上重新执行。

## 2. 演示前准备

提前完成以下检查：

- Docker Desktop 已启动，Linux Engine 正常；
- OpenClaw 可以正常运行；
- 不要移动项目目录或 `.openclaw/aegis-policy` 发布目录；
- 关闭无关窗口和消息通知；
- 将终端字号调大，建议 20—24；
- 保留至少 3 分钟演示时间，正常情况下约 60—120 秒完成；
- 不要在演示过程中关闭 Docker Desktop。

推荐提前完整运行一次，确认最终显示绿色的 `[ACCEPTED]`。

## 3. 一键启动方式

双击：

`demo_web/一键演示_OpenClaw_Skill准入.cmd`

如果中文文件名在资源管理器中显示异常，也可以双击完全相同的 ASCII 兼容入口：

`demo_web/Run_OpenClaw_Demo.cmd`

启动器直接使用 Windows 自带的 PowerShell 5.1，并显式按 UTF-8 加载中文演示程序，不要求另外安装 PowerShell 7。也可以在命令提示符中运行 `demo_web\Run_OpenClaw_Demo.cmd`。

默认每个阶段停顿 2 秒，并在结束后自动删除本次创建的临时 Skill。审计记录和 JSON 报告会保留。

## 4. 正式讲解稿

### 开场

看到标题后讲：

> 下面演示的是 Aegis Chain 与 OpenClaw 的真实安装前准入闭环。我们不直接运行来源未知的 Skill，而是先检查完整供应链包，再决定是否允许进入隔离试运行，最后才由 OpenClaw 提交安装。

> 本次选择了一组公开研究数据集中的配对样本：一个正常会议纪要 Skill，以及它的同名恶意变体。演示程序、Docker、OpenClaw 和审计数据库都在本机真实运行，不使用 GPU，也不调用云端大模型。

### 阶段一：环境与策略自检

屏幕显示 `[1] 环境与准入策略自检` 时讲：

> 首先验证安全链路自身是否可信。脚本会检查 OpenClaw 配置、Skill 安装策略、Docker Linux Engine 和审计运行环境。我们的动态策略设置为 required，也就是动态审计无法可靠完成时必须失败关闭，不能默认放行。

看到两行 `[PASS]` 后补充：

> 这里证明当前演示不是绕过策略直接复制文件，而是由 OpenClaw 在安装提交前主动调用 Aegis Chain。

### 阶段二：权威样本与完整性

屏幕显示 `[2] 权威样本身份与完整性核验` 时讲：

> 样本来自 SkillTrustBench 固定版本。脚本会核对数据集清单和每个文件的 SHA-256，任何文件发生改变都会立即停止演示，避免为了得到理想结果而临时修改样本。

显示相同主程序哈希后讲：

> 这两个 Skill 的名字相同，主 Python 程序也完全相同。恶意变体的变化藏在供应链包的其他文件中：它修改了 SKILL 指令，并增加了隐藏的工具覆盖脚本。

> 因此，只检查项目名称、主程序或功能描述是不够的，必须审查完整安装包。这也是我们选择这组样本的主要原因。

### 阶段三：正常 Skill 放行

屏幕显示 `[3] 正常 Skill` 时讲：

> 现在通过真实 OpenClaw 安装正常样本。系统先运行 Cisco Skill Scanner 和 Aegis 静态规则。如果静态结果达到阻断级别，后续脚本不会执行；只有静态可接受时，才进入 Docker 隔离试运行。

> 容器关闭外部网络，使用只读根文件系统、非 root 用户、最小权限、CPU、内存和进程数限制，也不挂载 Docker Socket。动态审计会观察网络、进程、敏感文件和其他高风险行为。

看到安装成功后讲：

> 正常样本获得动态清洁证明，OpenClaw 完成安装。系统还会逐文件比较安装前后的哈希，防止审计对象与最终安装对象不一致。

看到 `eligible=true`、`modelVisible=true` 后讲：

> 这里进一步证明它不只是生成了一个目录，OpenClaw 已经把这个 Skill 识别为模型可见、可使用的能力。

### 阶段四：恶意变体阻断

屏幕显示 `[4] 恶意同名变体` 时讲：

> 接下来安装外观和主程序相同的恶意变体。由于完整包中存在提示注入、部分远程执行链和异常隐藏脚本，静态策略直接给出 BLOCK。

看到 `[PASS] 恶意 Skill 被安装策略拒绝` 后讲：

> 阻断发生在安装提交前。恶意 Skill 没有进入 OpenClaw 工作区，也没有获得执行机会。这体现了“静态审计决定有没有资格试运行”，而不是把所有可疑代码都先运行一遍。

### 阶段五：审计证据

屏幕显示 `[5] 审计证据与失败关闭核验` 时讲：

> 现在读取追加写入的审计数据库，并重新计算哈希链。正常样本必须同时有 ALLOW 和 `AEGIS_DYNAMIC_EXECUTION_CLEAN`；恶意样本必须是 BLOCK，而且不能出现任何动态执行规则。

看到正常样本规则时讲：

> 这个 INFO 不是“绝对安全认证”，它是一条执行证明：固定镜像、安全门、遥测完整性和容器清理都通过，本次受控运行没有观察到阻断行为。

看到恶意规则时讲：

> 恶意样本命中了提示注入和执行链规则，动态执行次数为零。这样既获得检测效果，也避免为了检测而主动运行已经明确恶意的代码。

### 阶段六：零残留

屏幕显示 `[6] 容器清理与零残留核验` 时讲：

> 动态审计不能只关注检测结果，还必须验证隔离环境是否清理干净。这里会查询带 Aegis 后端标签的全部容器，并确认容器残留和恶意安装残留都为零。

### 阶段七：自动清理

屏幕显示 `[7] 清理本次演示对象` 时讲：

> 为了保证演示可以重复运行，脚本使用每次唯一的临时名称，并只删除本次新建的正常 Skill。既有 OpenClaw Skill、安装策略、审计记录和报告都不会删除。

### 最终总结

看到绿色 `[ACCEPTED]` 后讲：

> 演示结果表明，我们已经形成了“第三方 Skill、静态审计、Docker 隔离试运行、OpenClaw 安装或阻断、审计留痕”的完整闭环。

> 正常样本完成静态和动态验证后被放行；同名恶意变体在执行前被阻断；审计链有效，容器和恶意安装残留均为零，整个过程不依赖 GPU。

> 我们不宣称能够发现所有攻击，也不把一次干净运行解释为永远安全。当前创新点是把多种检测能力组织成可真实接入智能体平台、能够失败关闭并留下证据的工程化准入链路。

## 5. 评委可能追问

### 为什么恶意样本没有进入动态审计？

回答：

> 动态审计不是越多越好。静态阶段已经确认达到 CRITICAL 的样本，不应该再主动执行。我们的顺序是静态先筛选、动态再验证，恶意样本未执行本身就是安全控制生效的证据。

### `AEGIS_DYNAMIC_EXECUTION_CLEAN` 是否代表绝对安全？

回答：

> 不代表。它只证明固定容器、固定输入和本次执行没有观察到阻断行为，同时证明遥测和清理完整。条件触发型、延迟型或利用底层绕过的行为仍需要更多输入、内核级遥测和长期测试覆盖。

### 为什么使用 Docker，而不是 GPU 或大模型？

回答：

> 当前任务是确定性安全扫描和隔离执行，主要消耗 CPU、磁盘和进程启动时间，不需要 GPU。大模型可以用于语义复核和解释，但不应替代可复现的准入规则和失败关闭机制。

### 为什么两个安装过程需要十几到几十秒？

回答：

> 时间包括 OpenClaw 启动、完整包哈希、Cisco 和 Aegis 静态扫描、策略判定、Docker Engine 通信、镜像身份检查、容器创建、受控执行、遥测解析、容器清理和安装提交。恶意样本虽然不执行，也仍需完成静态分析和审计记录。

### `allowInsecurePath=true` 是否降低了安全性？

回答：

> 这是当前 OpenClaw Windows 稳定版无法自动识别 NTFS ACL 时的兼容声明。启用前，我们已经把策略发布到独立版本目录，并人工核验只有当前用户、SYSTEM 和管理员可以修改。该开关不关闭静态扫描、动态审计或失败关闭；如果目录权限没有经过核验，就不能启用。

### 为什么选择这两个样本？

回答：

> 它们来自同一固定版本公开数据集，名称和主程序完全相同，但恶意变体在包内增加隐藏文件并修改指令。它能非常直观地说明供应链审计必须覆盖完整包，而不能只看主程序或功能名称。

## 6. 现场异常处理

如果最终不是绿色 `[ACCEPTED]`：

1. 不要手工修改结果，也不要重复点击很多次；
2. 保留窗口，直接说明系统采用失败关闭，所以环境异常时不会放行；
3. 根据最后一行原因检查 Docker Desktop、OpenClaw 配置或样本哈希；
4. 可以展示已经固化的验收报告和两轮机器证据，但要明确说明这是此前成功运行结果，不冒充本轮现场结果。

最常见异常：

| 屏幕提示 | 处理方式 |
| --- | --- |
| Docker Engine 不可用 | 打开 Docker Desktop，等待状态变为 Running，再重新运行 |
| OpenClaw 配置校验失败 | 不继续安装，检查 `openclaw config validate --json` |
| 样本哈希不匹配 | 停止演示，恢复固定数据集，不要修改预期哈希 |
| 正常 Skill 未安装 | 保留失败记录，查看报告中的策略或 Docker 原因 |
| 容器有残留 | 不宣称通过，先查清残留容器来源并完成清理 |
