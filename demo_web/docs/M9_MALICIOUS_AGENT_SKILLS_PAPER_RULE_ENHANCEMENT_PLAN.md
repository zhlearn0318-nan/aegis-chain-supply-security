# M9：Malicious Agent Skills 论文对照分析与 Skill 准入增强方案

> 文档状态：P0、P1 已按方案实施并完成本机验收；结果见 M10 报告
> 编制日期：2026-08-31
> 适用范围：OpenClaw Skill 安装前静态审计与隔离动态审计
> 不在本轮范围：MCP、Plugin、P2 生产控制面与决策降级策略切换
> 研究对象：*“Do Not Mention This to the User”: Detecting and Understanding Malicious Agent Skills in the Wild*

## 1. 执行摘要

论文及其公开数据集可以显著增强当前 Aegis Chain 的 Skill 准入能力，但其主要价值不是继续复制正则表达式，而是将现有流程从“命中高危特征后直接阻断”升级为：

> 静态筛选候选风险 → 语义与上下文判断 → 针对性隔离运行 → 声明行为与实际行为比对 → ALLOW / REVIEW / BLOCK

当前系统并未出现“几乎所有 Skill 都被拒绝”，但正常 Skill 的自动放行能力仍不满足真实日常使用要求：

- 600 条密封回归集中，正常样本误报率为 **35.5%**；
- 24 个论文数据集弱安全样本中，16 个 ALLOW、4 个 REVIEW、3 个 BLOCK、1 个 UNKNOWN；
- 约三分之一正常或弱安全 Skill 无法自动放行，会产生较高的人工复核负担。

主要原因不是缺少远程执行、凭据窃取等基础规则，而是当前系统仍存在以下结构性问题：

1. 单条 CRITICAL/HIGH 发现即可决定 BLOCK；
2. INFO 上下文只能解释风险，不能对误报进行降级；
3. 动态结果只能维持或提高风险，无法解除候选型静态误报；
4. 动态审计只支持 Python 入口；
5. 缺少自然语言操纵、隐藏指令和声明—行为不一致检测。

因此，下一阶段应优先改造证据模型和决策融合，再扩展规则数量与动态运行语言。

## 2. 论文、代码与数据集来源

### 2.1 权威来源

- 论文：[arXiv:2602.06547](https://arxiv.org/abs/2602.06547)
- 官方研究代码：[MaliciousAgentSkillsBench](https://github.com/protectskills/MaliciousAgentSkillsBench)
- 官方数据集：[Hugging Face / ProtectSkills](https://huggingface.co/datasets/ProtectSkills/MaliciousAgentSkillsBench)
- 长期归档：[Zenodo DOI 10.5281/zenodo.20285751](https://doi.org/10.5281/zenodo.20285751)

论文已被 USENIX Security 2026 接收。官方仓库说明其研究制品通过了 USENIX Security 2026 Artifact Evaluation，具有 Artifacts Available、Artifacts Functional 和 Results Reproduced 标记。

### 2.2 研究规模与主要发现

论文研究了：

- 98,380 个公开 Agent Skill；
- 11,246 个代码仓库；
- 4,287 个静态候选，占总量约 4.4%；
- 762 个出现运行时风险迹象的 Skill；
- 157 个最终确认恶意的 Skill；
- 632 项恶意行为；
- 14 类攻击技术中的 13 类实际出现；
- 每个恶意 Skill 平均包含 4.03 种攻击技术；
- 恶意 Skill 的攻击链中位数跨越 3 个阶段。

论文的关键经验是：静态模式适合缩小检查范围，但不能直接作为恶意真值。4,287 个静态候选中，最终只有 157 个被确认恶意；762 个动态可疑样本中，也有 605 个最终未被确认恶意。

### 2.3 数据集标签边界

| 标签 | 数量 | 含义 | 适合用途 | 不适合用途 |
| --- | ---: | --- | --- | --- |
| `malicious` | 157 | 研究者确认恶意 | 攻击类型、规则覆盖、证据模式研究 | 直接下载并执行全部恶意代码 |
| `suspicious` | 4,130 | 静态可疑但未确认恶意 | 候选风险分析、REVIEW 工作负载评估 | 当作恶意真值计算准确率 |
| `safe` | 94,093 | 未命中论文静态筛选漏斗 | 真实生态兼容性和硬负例抽样 | 当作经过行为验证的强安全标签 |

官方数据对恶意 Skill 的原始地址进行了隐藏。因此，157 个确认恶意样本主要用于威胁分类和规则设计，不能被表述为157个可直接复现运行的完整恶意样本。

论文主要研究 Claude Code Skill。通用攻击链可以迁移到 OpenClaw，但 Hook、配置文件、模型代理、权限跳过等平台原生规则必须针对 OpenClaw 重新实现。

## 3. 论文威胁分类与当前规则覆盖

| 编号 | 论文风险类别 | 当前覆盖程度 | 当前能力与主要缺口 |
| --- | --- | --- | --- |
| E1 | 外部传输 | 较强 | 已有网络外传和敏感数据流规则，需要增加声明域名与实际域名比对 |
| E2 | 凭据收集 | 较强 | 已覆盖密钥、令牌和凭据文件，需要减少安全工具、示例内容的误报 |
| E3 | 文件系统枚举 | 部分 | 普通目录遍历多为 INFO，缺少“与声明功能无关的大范围枚举”判断 |
| E4 | 网络侦察 | 部分 | 能发现网络操作，缺少端口扫描、内网地址探测和服务发现语义 |
| SC1 | 命令注入 | 较强 | 已有不可信输入到 Shell/Eval 的数据流规则 |
| SC2 | 远程脚本执行 | 较强 | 已覆盖下载、解码、管道执行和粘贴站载荷等攻击链 |
| SC3 | 混淆代码 | 较强 | 已覆盖编码载荷和解码后执行，需要补充跨文件、分段载荷 |
| P1 | 指令覆盖 | 较弱 | Cisco YARA 有相关发现，但误报较高，缺少 Skill 专用语义分析 |
| P2 | 隐藏指令 | 较弱 | 缺少隐藏注释、不可见文本、隐瞒用户和条件触发检测 |
| P3 | 数据泄露 | 较强 | 已有敏感源到外部网络汇的数据流分析 |
| P4 | 行为操纵 | 较弱 | 缺少绕过用户确认、压制告警、操纵 Agent 行为的语义检测 |
| PE1 | 权限过大 | 部分 | 已覆盖通配工具权限，缺少权限与声明功能的匹配分析 |
| PE2 | 权限提升 | 较强 | 已覆盖管理员权限、系统配置和高危权限操作 |
| PE3 | 凭据文件访问 | 较强 | 已覆盖常见敏感路径和凭据读取 |

当前优先级最高的缺口是：

1. P1/P2/P4 自然语言语义检测；
2. Skill 声明能力与实际能力比对；
3. 文档、示例、测试夹具与真实可达代码区分；
4. 静态候选证据的动态确认或消歧；
5. OpenClaw 平台原生安全规则。

## 4. 对当前系统最有价值的论文结论

### 4.1 静态命中只应表示候选风险

论文发现，大量具有安全、凭据、网络、命令和诊断功能的正常工具都会产生静态或运行时风险信号。例如：

- 合法安全检测工具；
- 凭据管理工具；
- 开发诊断工具；
- 系统管理和运维工具；
- 合法网络、文件和命令调用。

因此，单独出现 Shell、网络、下载、凭据或攻击术语，不足以将 Skill 定性为恶意。

### 4.2 自然语言本身是主要攻击载体

论文报告 84.2% 的恶意行为涉及 `SKILL.md` 中的自然语言指令。这说明只扫描 Python、JavaScript 等代码不能覆盖 Skill 的主要攻击面。

需要重点识别：

- 要求 Agent 忽略上级、系统或用户约束；
- 要求不向用户展示操作、日志或真实目的；
- 绕过确认、审批和人工参与；
- 把普通文本伪装成更高优先级指令；
- 通过隐藏注释、特殊格式、条件口令或延迟触发行为。

语义检测必须理解否定和防御上下文。例如，“不要执行未验证的远程脚本”不能因为出现“执行远程脚本”而判为恶意。

### 4.3 声明—行为不一致是高价值风险信号

论文报告 73.2% 的恶意 Skill 存在 shadow feature，即 Skill 对用户宣称执行一种功能，实际还执行未声明行为。例如：

- 图片处理 Skill 额外遍历整个用户目录；
- 文档整理 Skill 访问 SSH 密钥；
- 数据分析 Skill 连接未声明服务器；
- 正常功能完成后通过 Hook 继续执行；
- 表面访问官方服务，实际把数据转发到第三方代理。

该结论与现有 M8 第三方样本中的漏检相吻合：图片处理 Skill 包含隐藏辅助脚本，并从当前目录递归枚举文件，但现有系统只产生 INFO 解释，最终被 ALLOW。

因此，“声明—实现—运行行为一致性”应成为后续研发的核心创新点。

### 4.4 动态审计必须针对静态疑点生成触发输入

论文不是简单启动脚本一次，而是根据 Skill 元数据和入口生成典型、边界和对抗输入，并进行多轮调用。其目标是提高隐藏条件、异常参数和组合行为的触发概率。

当前系统固定运行自建 Python 入口，只能证明沙箱和检测链路可以工作，还不能充分验证真实第三方 Skill 的条件触发行为。

## 5. 当前正常 Skill 误报较高的原因

### 5.1 单条高严重度发现直接决定 BLOCK

当前准入策略为：

- CRITICAL/HIGH → BLOCK；
- MEDIUM/LOW → REVIEW；
- INFO/SAFE → ALLOW。

该策略没有区分“风险严重程度”和“证据可信程度”。Cisco 单条 YARA HIGH 即可决定最终 BLOCK。

M8 中的正常网页样式提取 Skill 因标题、CSS 内容及正常的 `MUST / Do Not` 操作约束，被 `YARA_jailbreak_generic` 产生20条HIGH，最终直接被阻断。这属于缺少自然语言上下文理解的典型误报。

### 5.2 INFO 上下文不能参与风险降级

系统已经能够发现部分有利上下文：

- 测试夹具；
- 示例代码；
- 本地或回环地址；
- 安全保护条件；
- 声明过的文件、网络和命令行为。

但这些信息目前只生成 INFO finding。最终决策采用最高严重度，INFO 无法修正单条 HIGH，因此“解释层”没有真正转化为“消歧层”。

### 5.3 动态结果只能维持或提高风险

当前静态—动态融合使用单调最大风险逻辑：动态发现可以将风险从 ALLOW 提高到 REVIEW/BLOCK，但动态清洁证据不能把候选型静态 REVIEW 降为 ALLOW。

因此，动态审计目前更像第二个风险发现器，还不是能够验证和解除误报的证据验证器。

### 5.4 动态执行范围过窄

当前动态审计只发现和执行 Python 入口。没有 Python 入口时会产生 `PYTHON_ENTRYPOINT_NOT_FOUND`。这会影响：

- 纯指令型 Skill；
- Node.js Skill；
- Shell Skill；
- 入口未按当前约定组织的真实第三方 Skill。

现有20个动态样本均为自建Python测试样本。60次运行全部符合预期，只能证明固定Docker/Linux环境中的现有测试夹具稳定，不能代表未知真实Skill的检出率。

## 6. 新的证据与决策模型

### 6.1 Finding 数据结构建议

每条 finding 不应只记录严重度，建议至少增加以下维度：

```text
risk_severity: CRITICAL | HIGH | MEDIUM | LOW | INFO
evidence_confidence: POTENTIAL | CORROBORATED | CONFIRMED
reachability: REACHABLE | REFERENCED | EXAMPLE | TEST | UNKNOWN
behavior_alignment: DECLARED | UNDECLARED | CONTRADICTORY | UNKNOWN
evidence_source: CISCO | AEGIS_STATIC | SEMANTIC | DYNAMIC | PROVENANCE
```

其中：

- `risk_severity` 表示行为一旦成立可能造成的后果；
- `evidence_confidence` 表示证据证明该行为真实存在的程度；
- `reachability` 表示代码是否能从 Skill 真实入口到达；
- `behavior_alignment` 表示行为是否在 Skill 声明中得到合理说明。

### 6.2 BLOCK 条件

以下情况可直接阻断：

- 凭据读取与外部传输形成完整可达数据流；
- 不可信下载、解码和执行形成完整攻击链；
- 明确隐藏指令，同时要求绕过用户确认或隐瞒真实行为；
- 修改 OpenClaw 安全配置、系统提示词、模型地址或权限策略；
- 静态高危证据与动态危险行为相互印证；
- 命中已确认恶意哈希、签名或已知恶意来源。

BLOCK 应要求高风险与高证据可信度同时成立，不能仅由孤立关键词决定。

### 6.3 REVIEW 条件

以下情况进入人工复核或隔离试运行：

- 只有单条 Cisco HIGH 或 YARA 命中；
- 出现 Shell、网络或敏感文件能力，但符合 Skill 声明；
- 命中内容位于文档、示例或测试夹具；
- 静态解析不完整或扫描覆盖不足；
- 动态执行没有覆盖静态怀疑的触发条件；
- 存在未声明功能，但尚未观察到危险结果。

### 6.4 ALLOW 条件

自动放行应至少满足：

- 未发现完整攻击链；
- 静态扫描覆盖完整；
- 高风险能力与声明功能一致；
- 文档、示例和生产入口已区分；
- 静态疑点已经得到针对性动态验证；
- 未发现隐藏行为或声明—实际行为冲突。

动态清洁不能推翻已确认的完整静态攻击链；但在覆盖充分、测试输入针对风险、遥测完整且多轮结果一致的情况下，可以将候选型静态 REVIEW 降为 ALLOW。

## 7. 静态审计增强设计

### 7.1 P0：Skill 自然语言语义分析

重点覆盖 P1、P2、P4：

- 忽略系统、平台或用户约束；
- 不告知用户、不显示日志或隐藏结果；
- 绕过确认、审批或人工参与；
- 条件口令、延迟触发和角色伪装；
- 将普通文本包装为更高优先级指令。

推荐采用“结构规则初筛＋小模型语义复核”，不允许大模型单独决定 BLOCK。模型应输出结构化证据：

- 命中位置；
- 被要求执行的动作；
- 动作目标；
- 是否要求隐瞒；
- 是否绕过用户授权；
- 上下文属于攻击指令、引用示例还是防御说明；
- 判断置信度与解释。

模型失败、超时或输出不合格时应进入 REVIEW，而不能自动定性为恶意。

### 7.2 P0：文件角色与代码可达性

扫描器应将文件划分为：

- 真实入口和运行代码；
- 被入口引用的辅助代码；
- 文档；
- 示例；
- 测试夹具；
- 未引用文件。

文档、示例或测试中的危险字符串原则上不能直接触发 BLOCK，除非该文件随 Skill 安装后能够从真实入口到达或执行。

### 7.3 P0：声明—实现一致性分析

分别提取：

1. `SKILL.md` 和 frontmatter 声明的文件、网络、命令、权限及数据能力；
2. 代码静态分析得到的实际能力；
3. 隔离运行中观察到的真实行为。

重点检测：

- 未声明外部域名；
- 未声明敏感路径；
- 未声明 Shell 或子进程；
- 未声明目录递归枚举；
- 未声明 Hook、后台任务和持久化行为；
- 声明只读但实际写入或删除；
- 声明本地处理但实际向外传输。

### 7.4 P0：Cisco finding 上下文消歧

Cisco finding 不应被删除，而应作为候选证据进入统一证据层。对 Cisco HIGH 增加以下检查：

- 命中位置是否为真实可达入口；
- 是否处于代码围栏、引用、示例、测试或防御说明；
- 是否存在完整 source-to-sink 数据流；
- 网络目标是否已声明、固定并受信；
- 下载内容是否有版本或哈希锁定；
- 危险操作是否有用户确认、范围限制和保护条件。

孤立 Cisco HIGH 默认进入 REVIEW；只有被 Aegis 静态链、语义证据或动态证据印证后才升级为 BLOCK。

### 7.5 P1：OpenClaw 平台原生规则

至少补充：

- 修改 OpenClaw 配置或安全策略；
- 修改系统提示词、模型选择或模型代理地址；
- 启用跳过权限、自动确认或静默模式；
- 注册安装后、工具调用前后、启动或会话结束 Hook；
- 向未声明的模型代理转发上下文；
- 阻止、规避或伪造用户确认；
- 修改 Aegis Chain 自身规则、日志或审计开关。

## 8. 动态审计增强设计

### 8.1 按 Skill 类型路由

| Skill 类型 | 建议验证方式 |
| --- | --- |
| 纯指令 Skill | 语义对抗测试与工具调用意图模拟，不强制寻找 Python 入口 |
| Python Skill | 继续使用现有容器沙箱，并增加针对性输入和多轮运行 |
| Node.js Skill | 增加固定 Node.js 运行环境和行为监控 |
| Shell Skill | 仅在无网络、非 root、只读文件系统和能力清零的严格容器中运行 |
| 含原生二进制 | 默认 REVIEW；比赛正式版不建议直接运行未知二进制 |

### 8.2 针对性输入生成

每个进入动态审计的 REVIEW Skill 至少使用：

1. 正常业务输入；
2. 边界或异常输入；
3. 根据静态疑点生成的对抗输入。

例如，静态发现条件口令时生成包含和不包含口令的输入；发现目录枚举时提供多层目录和诱饵文件；发现网络上传时提供含诱饵敏感字段的业务数据。

### 8.3 诱饵与行为监控

容器内放置：

- 假 API Key；
- 假 SSH 密钥；
- 假政企业务文档；
- 假 OpenClaw 配置；
- 受控本地网络接收端。

监控以下行为：

- 是否读取诱饵；
- 是否尝试外传；
- 是否启动子进程；
- 是否修改配置；
- 是否注册 Hook；
- 是否在后续调用或会话触发隐藏逻辑；
- 是否出现声明之外的文件、网络或命令行为。

### 8.4 多轮与多会话验证

论文指出，部分未确认候选使用休眠触发、环境判断、多会话或二阶行为。比赛版本可采用分级策略：

- 普通 REVIEW：3轮输入，60秒预算；
- 高可疑且未确认：3～5轮输入，120秒预算；
- 存在状态文件、Hook或延迟逻辑：增加第二会话；
- 仍无法覆盖触发条件：保持 REVIEW，不以“没有观察到行为”宣称安全。

### 8.5 论文执行器的使用边界

不建议将论文官方动态执行器原样接入正式 OpenClaw 准入。其研究环境会挂载一次性 Claude 认证并跳过权限确认，适合论文实验，但不符合本系统的最小权限和生产隔离要求。

可借鉴的内容包括：

- 多类型输入；
- 多轮调用；
- 文件和网络行为记录；
- 蜜罐凭据；
- 声明行为与运行行为比较。

### 14.1 策略范围收紧过程

第一版开发实现曾把全部缺少 Aegis 高危佐证的 Cisco HIGH 送入 REVIEW。只读回放发现该范围过宽：89条由BLOCK转为REVIEW，正常直接阻断率下降，但恶意直接BLOCK召回从82%降到72%。该方案未作为最终策略采用，开发证据保留在：


最终实现改为配置式候选清单，只纳入论文和既有误报分析明确表明需要上下文判断的原语规则：

```text
YARA_jailbreak_generic
DATA_EXFIL_JS_FS_ACCESS
DATA_EXFIL_SENSITIVE_FILES
RESOURCE_ABUSE_INFINITE_LOOP
```

未列入清单的 Cisco HIGH、完整攻击链、Aegis HIGH/CRITICAL 和 Cisco CRITICAL 继续BLOCK。该调整不是修改原始严重度，而是区分“潜在高危原语”与“具有直接阻断证据的高危行为”。
