# M39 E05 OpenClaw 端到端稳定性与性能实验结果

## 1. 结论

E05 的核心准入门通过：正常矩阵 36/36 达到预期终态，非放行样本未发生安装，审计接口与 PDF 决策全部一致；并发 1/3/5 时实际扫描数始终不超过 1；本地模型、Cisco Scanner 和 Docker 三类故障均未回退为 `ALLOW`。

工程限制也必须保留：Docker Desktop 被主动停止后，自动恢复命令在 Windows 通信套接字上挂起，最终通过移动通信目录并重新启动 Docker 的人工恢复流程恢复。因此可以声称“Docker 故障时安全失败关闭”，不能声称“Docker 故障后全自动自愈”。

三组共 6 个竞争请求均得到明确忙碌终态，未出现永久中间态。该结果支持“当前单机版通过全局串行化避免多个不可信 Skill 同时占用动态审计资源”，不代表系统已具备生产级任务队列或水平扩展能力。

## 4. 故障失败关闭

证据目录：`artifacts/experiment/2026-09-08-m15-e05-faults-v1/`

| 故障 | 决策 | 安装 | 依赖恢复 | 判定 |
|---|---|---|---|---|
| 本地模型超时 | WARN | 拒绝 | 配置原哈希恢复 | 失败关闭通过 |
| Cisco Skill Scanner 不可用 | BLOCK | 拒绝 | 扫描器原哈希恢复 | 失败关闭通过 |
| Docker 不可用 | WARN | 拒绝 | 人工恢复；自动恢复失败 | 失败关闭通过，自愈不通过 |

本地模型故障仅在候选 Skill 已含“模糊控制语句”时要求人工复核；普通无风险 Skill 不因模型缺失被普遍拒绝。模型仍不能单独产生 `BLOCK`。

Docker 故障证据为审计序号 215，命中 `AEGIS_DYNAMIC_TELEMETRY_INCOMPLETE` 与 `AEGIS_DYNAMIC_EXECUTION_INCONCLUSIVE`，审计链有效，对应 PDF SHA-256 为 `939416b5cc9fbc7f87a2431d5aaaf6e7682e045ab93b2f9decbd6a7d4c7dce33`。

## 5. 冒烟发现与修复

1. 正式页面使用 `WARN` 表达“需要复核且不可安装”，v1 合同误写为 `REVIEW`；v2 在正式运行前修订展示口径，不改安全决策。
2. 原更新样本自身含未声明进程能力，完整准入正确返回 `WARN`；改为从已获 `ALLOW` 的样本派生，仅加入无执行能力版本标记，确保前后哈希不同后再验证确认更新。
3. 第一轮长批次复用了一个 30 分钟页面令牌，在第 32 项过期；修正为每个独立场景重新获取短期令牌，并逐场保存检查点。插件的令牌期限未被放宽。
4. 模型失败原先只留下 INFO，模糊控制语言仍可能放行；现仅对“已有模糊信号且模型调用失败”的候选提升为 WARN，避免把证据缺失当成安全。

失败冒烟目录和收据均保留，未覆盖：

- `2026-09-08-m15-e05-openclaw-e2e-smoke-v1/`
- `2026-09-08-m15-e05-openclaw-e2e-update-smoke-v1/`
- `2026-09-08-m15-e05-openclaw-e2e-update-smoke-v2/`
- `2026-09-08-m15-e05-openclaw-e2e-v2/`

## 6. 可对评委使用的准确表述

> 系统在真实 OpenClaw 插件 HTTP 闭环中完成 12 类场景、3 轮共 36 次验收，预期决策、安装门、审计和 PDF 一致性均为 100%；普通单次闭环 P95 为 48.635 秒。并发 5 时仍只允许一个不可信 Skill 进入审计引擎。模型、Cisco 扫描器和 Docker 故障均不会回退为放行。Docker Desktop 故障后目前需要人工执行恢复流程，尚未实现可靠的全自动自愈。
