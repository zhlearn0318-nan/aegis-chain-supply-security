# D3-D Skill 运行时闭包平台接入 v1 计划

## 1. 实验身份与选定路线

- run id：`2026-08-23-skill-closure-platform-dev-v1`
- 分支：`dynamic-audit-v1`
- 层级：`auxiliary/dev`
- 接受基线：D3-C `2026-08-23-skill-runtime-closure-dev-v1`
- 基线提交：`4b4e843`
- 选定路线：复用现有管理员动态任务、SQLite 持久化和前端轮询机制，新增无请求体的 Skill 闭包专用触发端点；页面展示运行前后清单与新增风险，但保持 `policy_effect=none`。

## 2. 研究合同

- 研究问题：D3-C 已验收的 Skill 运行时闭包能否在不扩大执行输入面、不改变准入决策的前提下，通过统一平台完成管理员触发、后台执行、脱敏持久化和页面展示？
- 零假设：平台允许请求体或用户执行参数、管理员鉴权退化、任务无法完成、D3-C 关键指标退化、响应/数据库泄漏令牌或生成原文、工作区未清理、页面无法构建，或最终决策发生变化。
- 备择假设：专用端点仅接受管理员令牌且拒绝请求体；真实 API 任务完成并保留 D3-C 59/59、3/3、2 条运行时风险和 0 决策变化；数据库与响应无令牌/原文；页面可展示新增文件与风险且构建通过。
- 最强替代解释：后端任务成功但前端只展示静态占位数据。控制方式是页面完全从任务详情中的 `closure` 字段渲染，API 客户端与真实 API 端到端验收分别验证。

## 3. 基线与可比性

- D3-C 固定 fixture、镜像、配置、安全门、Cisco + Aegis 静态管线和指标定义保持只读语义。
- 原有 `aegis-safe-dynamic-fixtures-v1` 任务继续可用，数据库表不迁移。
- 新增平台指标不替代 D3-C 指标，只验证 HTTP、鉴权、持久化、清理和 UI 可用性。
- 不引入新数据集、不执行第三方 Skill、不联网、不拉取镜像、不使用 GPU 或云。

## 5. 验收指标

- 新端点：正确令牌返回 202；缺失/错误令牌返回 401；请求体返回 400。
- 真实任务：`status=completed`，D3-C 接受门 59/59，新增/提升/哈希 3/3/3，运行时风险 2，Cisco 扫描 2 次。
- 安全：`decision_changes=0`，原文泄漏、令牌泄漏、第三方执行、互联网、镜像拉取、容器残留、工作区残留均为 0。
- 持久化：任务详情和 SQLite 均包含脱敏清单与规则结果，不包含管理员令牌或生成文件原文。
- 兼容：原有基础动态 API 测试继续通过。
- 前端：API 单元测试通过，生产构建通过，页面源代码包含基于任务结果的文件和风险渲染。
- 完整后端回归全部通过。

## 6. 执行设计

- minimum：模型、端点、worker 和页面源代码完成，专项测试通过。

- maximum：浏览器自动化视觉验收和并发任务限流，延后处理。
- 运行预算：一个 D3-C 固定 fixture；容器 ≤10 秒；两次 Cisco 扫描各 ≤150 秒；整体预计 ≤30 秒。
- 停止条件：全部预登记指标通过、完整回归与前端构建通过、证据哈希一致。
- 放弃条件：必须开放上传代码/路径/命令、放宽 Docker 安全合同或改变最终准入决策。
