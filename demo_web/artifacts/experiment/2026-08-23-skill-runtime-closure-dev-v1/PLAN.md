## 2. 研究合同

- 研究问题：受控 Skill 在初始目录未暴露目标风险、运行时新增文件后，目录前后清单能否完整识别新增内容，并由现有静态审计链路找回运行前不可见的风险？
- 零假设：运行前后清单不完整、新文件数量或哈希不符、出现越界路径/软链接/超限内容、静态提升未发现运行时风险、Docker 安全门失败、保留原始内容、容器残留或改变既有最终决策。
- 备择假设：准确识别 3 个新增文件，指令/脚本/配置各 1 个，哈希 3/3 验证；现有静态链路在运行后新增至少 1 条运行前不存在且定位到新增文件的风险；全部 Docker 门通过，原始内容泄漏、第三方执行、残留与决策变化均为 0。
- 最强替代解释：fixture 自报“新增文件”且审计器只相信其声明。控制方式是宿主侧独立解码受限内容、复算哈希、重建前后目录、重新运行既有静态分析器并独立计算差集。

- 动态遥测基线：`2026-08-23-mcp-kernel-telemetry-dev-v1`，作为互补证据，不做数值优越性比较。
- 固定镜像：`public.ecr.aws/docker/library/python@sha256:dd29372629eeba2dd003fd9e9d35a5b8236c44727875a0364254b5127af88e65`，`pull=never`。

## 4. 样本与边界

- 仅执行 1 个自建、哈希锁定的确定性 fixture。
- 初始 Skill 目录只含固定的根 `SKILL.md` 和无害说明文件。
- 运行时仅生成 3 个永不执行的审计素材：指令 Markdown、Python 脚本和 JSON 配置。
- 生成脚本中的危险模式仅作为静态检测字符串，不调用、不导入、不执行。
- 不执行第三方 Skill，不接受用户路径、用户命令或用户代码，不联网、不拉镜像、不使用 GPU/云。

## 5. 必须指标

- Docker：镜像门 4/4、inspect 门 24/24、运行时门 12/12。
- 清单：`materialized_files_expected=3`、`observed=3`、`lifted=3`。
- 类型：instruction/script/config 各 1。
- 完整性：新文件哈希验证 3/3，删除和修改均为 0。
- 闭包：`closure_coverage_rate=1.0`，不安全路径、软链接、超限和不支持类型均为 0。
- 静态提升：Cisco 调用前后各 1 次；Aegis 既有分析器完整运行；至少 1 条新增风险定位到运行时文件；`runtime_only_risk_recovered=1`。
- 负面指标：原始生成内容泄漏、第三方样本执行、互联网、镜像拉取、GPU、容器残留、静态最终决策变化均为 0。

## 6. 实现与停止条件

- 最小：清单、路径、哈希、大小、类型与脱敏反例单元测试通过。
- solid：真实 Docker 完成生成，宿主重建目录并完成 Cisco + Aegis 前后静态扫描，所有接受门通过。
- 最大：第三方 Skill 的受控审批执行、系统调用级内容来源追踪和多语言动态生成，不在本轮范围。
- 运行预算：单 fixture，容器 ≤10 秒；两次静态扫描各 ≤150 秒；CPU 0.5、内存 256 MiB。
- 停止条件：正向门全部通过、负面指标为 0、完整后端回归通过并形成可复核证据。
- 放弃条件：需要放宽容器权限、挂载 Docker Socket、联网安装或执行第三方样本。
